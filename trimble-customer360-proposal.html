Record Linkage Pipeline — Python + Splink Proven at Infosys

Customer names appear differently across systems: "Trimble Inc.", "TRIMBLE INCORPORATED", "Trimble Field Systems". Exact matching fails. Splink uses probabilistic record linkage -- comparing name, email domain, phone, and address across sources with weighted match scores. Records above the threshold are merged into a single golden customer record. Below the threshold goes to manual review.

1

Ingest Raw Records

Pull customer entities from CRM, ERP, Licensing, and Marketing into Snowflake Bronze as-is

2

Standardize & Block

Normalize names, emails, addresses. Block on email domain + company prefix to limit comparison pairs

3

Splink Scoring

Run Python Splink EM algorithm -- assigns match probability (0.0–1.0) to every candidate pair

4

Threshold Decision

Score ≥ 0.85 → auto-merge. 0.60–0.84 → review queue. < 0.60 → treated as distinct

5

Golden Record

Write unified customer entity to Snowflake Gold — single customer_id with all source attributes joined

Phase 1

Audit & Catalog

2 weeks
  • Document every Domo DataFlow: inputs, logic, outputs
  • Identify dependencies between DataFlows and downstream cards
  • Flag high-risk transformations that need equivalent dbt models
  • Prioritize: which pipelines break the most if they fail?
Phase 2

Bronze Ingestion

3 weeks
  • Set up Snowflake schemas: raw, staging, analytics
  • Build Airflow DAGs for each source system
  • Implement CDC (change data capture) for incremental loads
  • Enforce raw-zone immutability -- Bronze is append-only
Phase 3

Silver Transformation

4 weeks
  • Rebuild every Domo DataFlow as a modular dbt model
  • Add dbt tests: not_null, unique, accepted_values, referential integrity
  • Set up GitHub CI/CD: PR-based review before any model deploys
  • Run Silver parallel to Domo -- validate output parity before cutover
Phase 4

Gold & Customer 360

4 weeks
  • Run Splink probabilistic matching across Silver customer entities
  • Build dim_customer golden record in Gold layer
  • Deploy Python classification algorithms via Snowpark stored procedures
  • Build fact tables: fact_usage, fact_revenue, fact_support
Phase 5

BI Reconnect

2 weeks
  • Reconnect Domo cards to Snowflake Gold via direct connector
  • Validate KPI parity: every dashboard number matches pre-migration baseline
  • Train business stakeholders on new self-serve analytics capabilities
  • Stakeholder sign-off before final cutover
Phase 6

Cutover & Handover

1 week
  • Deprecate all Domo DataFlows -- no more dual-running
  • Snowflake declared sole source of truth
